## 2. Жизненный цикл запроса (Request Lifecycle)

Как запрос клиента превращается в запись в базе данных и возвращается обратно:

```text
[ Клиент: curl / браузер / мобилка ]
         │  HTTP POST /businesses + JSON Body
         ▼
[ 1. Express App: src/index.ts ]
         │  app.use(express.json())  <-- парсит сырой текст в JS-объект req.body
         ▼
[ 2. Роутер: src/routes/businesses.ts ]
         │  Маршрутизация: сопоставляет метод (POST) и URL (/businesses)
         ▼
[ 3. Валидатор: src/schemas/business.schema.ts (Zod) ]
         │  safeParse(req.body)
         ├──> [Ошибка] ──> Возврат 400 Bad Request (клиент прислал мусор)
         └──> [Успех]  ──> Чистые, типизированные данные
         ▼
[ 4. ORM: Prisma Client ]
         │  db.business.create({ data: ... })
         ▼
[ 5. База данных: PostgreSQL в Docker ]
         │  Выполняет SQL: INSERT INTO "Business" ... RETURNING *
         ▼
[ 6. Ответ клиенту: res.status(201).json(business) ]
```

## 4. База знаний: концепции и термины (🔴 Critical)

### Что такое `process` и `process.env`?
* В Node.js глобальный объект `process` представляет запущенный процесс операционной системы.
* `process.env` — это объект, содержащий переменные окружения (*Environment Variables*).
* Зачем это нужно: На разных машинах (твой ноутбук, тестовый сервер, продакшен) настройки различаются (порты, пароли к базе данных, секретные API-ключи). Мы не зашиваем их в код (hardcode), а читаем из окружения: `process.env.PORT ?? 3000`.

### Что такое `Router` в Express и зачем `app.use()`?
* **Router** — это мини-приложение Express, изолированный сборщик маршрутов.
* Вместо того чтобы сваливать сотни ручек в один `index.ts`, мы группируем связанные эндпоинты по предметным областям в отдельные файлы:
  * `health.ts` — всё, что касается мониторинга здоровья;
  * `businesses.ts` — всё, что касается управления бизнесами.
* Метод `app.use(router)` подключает пачку маршрутов из роутера к основному серверу `app`.

### Как устроен поток выполнения роута (`req`, `res`)?
1. Клиент шлет запрос: `POST http://localhost:3000/businesses`.
2. Сервер находит соответствующий обработчик по совпадению HTTP-глагола (`POST`) и пути (`/businesses`).
3. Express передает в обработчик два ключевых объекта:
   * `req` (*Request*) — входящие данные (заголовки, параметры URL, тело запроса `req.body`).
   * `res` (*Response*) — интерфейс для отправки ответа клиенту (`res.status(201).json(...)`).

### Почему `async` стоит у всего роутера, а `await` — только в некоторых местах?
* Любая работа с сетью или диском (например, запрос к PostgreSQL) занимает время (миллисекунды). В JavaScript такие операции **асинхронные** и возвращают `Promise` (обещание вернуть данные позже).
* Ключевое слово `async` перед функцией обработчика говорит Express и Node.js: «Внутри этой функции могут быть долгие операции, которые не должны блокировать поток выполнения».
* Ключевое слово `await` мы ставим **только** перед операциями, возвращающими Promise (например, `await db.business.create(...)`), чтобы код дождался ответа от базы данных перед тем, как формировать HTTP-ответ `res.json(...)`. Если операция синхронная (например, простая проверка условия или вызов математической функции), `await` перед ней ставить не нужно.

### Что такое `emit` и «заэмитить»?
* Слово **Emit** переводится как «излучать», «выпускать», «генерировать наружу».
* В программировании термин используется в двух контекстах:
  1. **События (Event-driven architecture):** Когда один компонент говорит «что-то произошло» (`eventEmitter.emit('order_created')`), а другие компоненты слушают это событие.
  2. **Генерация артефактов компилятором/инструментом:** Когда CLI-инструмент создает файл на диске. Например, команда `tsc` эмитит (генерирует) `.js` файлы из `.ts`, а команда `prisma contract emit` генерирует файл контракта схемы на диск.

## 5. Детальный разбор Zod-схемы (`src/schemas/business.schema.ts`)

Давай разберем файл построчно:

```typescript
import { z } from "zod";

// 1. z.object() — описывает, что входящие данные должны быть JSON-объектом {}
export const createBusinessSchema = z.object({
  // Обязательная строка: минимум 1 символ (не пустая), максимум 255
  name: z.string().min(1, "Name is required").max(255),

  // Необязательная строка: клиент может либо прислать строку до 100 символов, либо не присылать поле вовсе
  category: z.string().max(100).optional(),

  // Обязательный город: минимум 1 символ, максимум 100
  city: z.string().min(1, "City is required").max(100),

  // Необязательный телефон
  phone: z.string().max(50).optional(),

  // Необязательное поле, но ЕСЛИ прислано — должно соответствовать формату URL
  websiteUrl: z.string().url("Invalid URL format").optional(),
});

// 2. .partial() — берет готовую схему и делает ВСЕ её поля опциональными (.optional())
// Это идеально подходит для PATCH-запросов, где клиент может обновить только одно поле (например, только телефон)
export const updateBusinessSchema = createBusinessSchema.partial();

// 3. z.infer — магия TypeScript!
// Нам не нужно вручную писать `interface CreateBusinessInput { name: string; ... }`.
// TypeScript автоматически выводит тип прямо из нашей runtime-схемы Zod.
export type CreateBusinessInput = z.infer<typeof createBusinessSchema>;
export type UpdateBusinessInput = z.infer<typeof updateBusinessSchema>;
```
